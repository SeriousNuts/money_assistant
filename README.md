# Money Assistant — восстановление исходников

Этот проект заново восстановлен из старого checkout `master` и поведения APK `1.2-design`.
Исходники версии 1.2, ранее использованные для публикации этого APK, были утрачены;
**это новая реализация**, а не идентичный исходный код релиза. Старые классы сохранены в
`app/src/main/java` для справки, приложение компилируется из `app/src/modern/java`.
Оформление экранов версии 1.4.1 повторяет композицию и палитру опубликованных
изображений версии 1.2; добавленный редактор чека выполнен в том же стиле.
Следующие исправления выходят как 1.4.2, 1.4.3 и далее; переход на 1.5 —
только по запросу владельца проекта.
Текущие изменения в исходниках после 1.4.1 **ещё не выпущены как 1.4.2**.

## Сборка в Linux без sudo

```bash
git clone https://github.com/SeriousNuts/money_assistant.git
cd money_assistant
bash toolchains/setup.sh
source toolchains/activate.sh
bash gradlew --no-daemon --max-workers=2 :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Нужны `curl`, `tar`, `unzip` и доступ к Google Maven и Maven Central.
`toolchains/setup.sh` устанавливает JDK 11 для Gradle, JDK 21 для sdkmanager,
Android SDK 30 и 33, Build Tools 30.0.2 в `~/.local/`. Переменная
`MONEY_JDK11` позволяет выбрать свой путь к JDK 11.

APK: `app/build/outputs/apk/debug/app-debug.apk`. Для Firebase-входа локально
положите конфигурацию Android-приложения `app/google-services.json` (она не
коммитится). Без неё приложение собирается и работает в локальном деморежиме.
Никогда не коммитьте `github.properties`, `google-services.json`, ключи подписи
или файлы сборки. Исторические конфигурационные файлы удалены из текущего индекса
Git, но могут оставаться в истории репозитория — ранее использованные секреты
следует отозвать и перевыпустить.

Если 1.2 установлена и прежний ключ подписи утрачен, можно **без удаления 1.2**
проверить отдельную демоверсию с другим идентификатором пакета:

```bash
bash gradlew --no-daemon :app:assembleDebug -PdemoSideBySide=true
```

Этот APK также находится в `app/build/outputs/apk/debug/app-debug.apk` (сохраните
его отдельно до следующей сборки). Он работает только локально и **не переносит
демоданные из установленной 1.2**: Android изолирует данные разных пакетов.
Для проверочной сборки с номером `1.4.2-rc6` добавьте `-PverificationApk`; обычная
сборка сохраняет номер прежнего выпуска до решения о релизе 1.4.2.
Для независимой проверки на телефоне безопаснее использовать демопакет:

```bash
bash gradlew --no-daemon :app:assembleDebug -PdemoSideBySide=true -PverificationApk=true
```

Проверочный APK, подписанный локальным отладочным ключом, нельзя установить
поверх приложения 1.2 с другим ключом. Не удаляйте 1.2 ради установки полного APK.

### Запуск на эмуляторе компьютера

На Linux с поддержкой KVM можно проверить все экраны без телефона и Android Studio:

```bash
bash toolchains/setup-emulator.sh            # однократно: Android 11, Pixel 3a
bash toolchains/run-on-emulator.sh           # соберёт, установит и откроет приложение
bash toolchains/run-on-emulator.sh --demo    # вместо полной сборки: отдельный демопакет
```

Окно эмулятора открывается отдельно; после закрытия терминала оно остаётся запущенным.
Для выключения: `~/.local/android-sdk/platform-tools/adb emu kill`.
Если установщик предупреждает о `/dev/kvm`, включите аппаратную виртуализацию
в BIOS/UEFI и выдайте пользователю доступ к группе `kvm`. Образ Android занимает
несколько гигабайт. `bash toolchains/start-emulator.sh` запускает только устройство,
если проект уже собран и приложение ставить не нужно.

## Функции

Деморежим запускается кнопкой «Попробовать без регистрации» либо с публичными
`demo@money.local` / `demo123`. Данные не отправляются в Firebase, сохраняются
в приватном `demo-ledger-v1.bin`. Приложение читает файл старого Java-формата 1.2
и сохраняет его в новом JSON-формате, включая уже отмеченные оплаты и удаления.
Облачные счета версии 1.2 читаются из документов счёта и участников `/{uid}`.

Расчёты ведутся в копейках. Можно добавить участников вручную или выбрать сразу
нескольких из контактов (с поиском и разрешением на доступ к контактам),
разделить сумму поровну, отметить/отменить оплату, удалить счёт, отправить
текст расчёта через системное меню. В редакторе доступна фотография чека через
системную камеру или выбор изображения, выделение областей пальцем, ручной ввод
названия/суммы позиции и выбор плательщиков. Общая позиция делится между
выбранными участниками до копейки и переносится в редактор. После съёмки или выбора
фото встроенная офлайн-модель Tesseract (`rus+eng`, tessdata_fast 4.1.0) предлагает
позиции с суммами и рамками; служебные строки и неуверенные результаты отсеиваются.
Для фото с несколькими чеками и фоном есть кнопка «Распознать выделенную область»:
выделение не обрезает исходное фото. Названия, суммы и доли нужно проверить перед
переносом. Обычное касание фото больше не открывает диалог: ручное добавление
позиции включается отдельной кнопкой и требует выделения области пальцем.
Офлайн OCR не гарантирует правильной разметки кривых и перекрытых чеков: снимайте
один чек крупно; доступно повторное распознавание и ручная правка.

Если офлайн-распознавание ошибается, на экране чека есть **«Распознать через Gemini
(онлайн)»**. Получите собственный API-ключ в [Google AI Studio](https://aistudio.google.com/apikey),
выберите тариф Free (его доступность и квоты зависят от аккаунта и региона),
введите ключ в приложении и подтвердите отправку **каждого фото**. Модель
`gemini-3.5-flash-lite` получает уменьшенное изображение по HTTPS и предлагает
только названия и итоговые цены товаров; список можно править перед сохранением.
Фото не отправляется при обычной съёмке, распознавании офлайн или без явного
подтверждения. Ключ хранится зашифрованным в Android Keystore, не входит в APK
и удаляется кнопкой «Удалить ключ». При бесплатном тарифе Google может использовать
отправленные данные для улучшения продуктов; **не отправляйте приватные чеки без
согласия**. Квоты могут закончиться, а при подключённом к проекту биллинге
запросы могут быть платными — проверьте тариф в AI Studio. Без ключа офлайн
распознавание и ручная разметка работают как раньше. Сетевой режим без ключа
на настоящих чеках пока не проверен; распознанные суммы всегда перепроверяйте.
Если приложение сообщает HTTP 400, в новой проверочной сборке выводится безопасная
причина: отклонённый ключ, недоступный бесплатный тариф или ошибка формата запроса.
Ключи, отправленные в чат/публичные места, **нужно отозвать и заменить**. Проверить
новый ключ на пустой тестовой картинке (без отправки личного чека) можно на ПК:

```bash
python3 toolchains/check-gemini.py
```

Скрипт запросит ключ скрытым вводом, не сохранит и не напечатает его. Отправляйте
для диагностики только выведенные код HTTP, статус и причину — **не сам ключ**.
Если выйти из создания счёта, он сохраняется отдельно как черновик на
главном экране, вместе с разметкой и несохранённым фото; можно продолжить или
удалить его. Черновики разделены между деморежимом и учётными записями и не
попадают в список сохранённых счетов. В текущих исходниках
сохранённый счёт можно переименовать, изменить ручные доли и добавить людей
с указанным долгом или с 0 ₽; уже отмеченные оплаты не сбрасываются. Удаление
участников сохранённого счёта запрещено из-за индексов позиций и оплат.
Ручные долги **складываются** с долями по позициям всех чеков. Несколько чеков
хранятся отдельными записями с собственными фото: обзор, поиск по позициям,
добавление и удаление чека. Старые `lines`/`<bill-id>.jpg` читаются без потери.
Фото хранится только в приватной папке
приложения; синхронизируются лишь записи и суммы, но не изображения.

## Ограничения и безопасность данных

Сборка из нового окружения подписана **другим отладочным ключом**, чем APK 1.2.
Её нельзя установить как обновление поверх APK 1.2 без прежнего ключа подписи.
**Не удаляйте установленную 1.2 без сохранения её локальных данных.** Для
совместимого обновления необходим оригинальный ключ подписи; если он утрачен,
потребуется отдельная стратегия миграции данных. Облачный вход требует
собственной конфигурации Firebase. Новое фото чека не синхронизируется между
устройствами; старые фото удаляются системой вместе с данными приложения.

Проверены сборка, модульные тесты и Android lint; встроенный русский OCR проверен
инструментальным тестом на эмуляторе Android 11. Библиотека Tesseract4Android 4.2.0
подключена через JitPack, языковые файлы (Apache-2.0) поставляются в APK.
На эмуляторе Android 11 проверены установка, сохранение участника с 0 ₽,
открытие обзора чеков и фото через системную камеру. Миграция старых данных,
несколько чеков и фото, сохранение оплат и защита от устаревшей правки покрыты
локальными тестами. Обновление через Firestore, камера и контакты на физическом
устройстве не проверены; перед выпуском 1.4.2 нужны эти проверки, а также
ручные сценарии в обеих темах и проверка ошибок/повторных попыток.
